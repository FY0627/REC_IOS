# 识别模板（用户在本机做）

通用读法认不准的写法，用户可以自己做模板（`UI/Pending/TemplateEditorView.swift`，和记一笔一样是弹出的表单）：在「我的 › 自动记账 › 识别模板」点右上角「导入」，名称、类型和原文排在同一张卡片上（像写邮件，类型是一个菜单：支出、退款、收入、转帐转出、转帐转入），在原文输入框里直接粘贴或打一条通知，光标离开就按通用读法认一遍（输入框右下角的圆按钮从相册选截图，做截图模板）；或者在「待处理」里点一条通知的「做成识别模板」。

1. 原文是整理过的正文（`MessageParser.cleaned`，和识别时看到的一样；粘贴的原文先整理再显示），用系统文字选择选中金额（必选）、尾号、对方，再和记账一样选支出 / 收入 / 转帐（支出可以标成退款，转帐选这张卡转出还是转入）。交易性质和方向由这几样推出来（`MessageTemplate.fields`），原来的性质还在同一类里就保留（手续费、工资、还款等）。粘贴后先用通用读法猜好金额位置和类型。
2. 模板只取选中内容所在的句子；前后文字（汉字、字母）少于 8 个时往前多取几句（例如邮件里金额单独一行），仍然太少就不让保存。
3. **去敏**：模板只保存写法——选中的位置换成占位，其他数字一律换成「任意数字」，不保存原文的任何数字；其余文字原样保留，用来认出同一种通知。
   模板只保存在这台 iPhone（`message_templates` 表），不发给任何人。
4. 识别时**模板优先于通用读法**（验证码除外）：文字一致（空白多少不限、不分大小写）、数字可以不同就算认出，
   用模板认出的那一笔代替通用读法的结果；时间和交易参考号仍由通用读法从正文里找。之后的匹配账户、去重、入账不变。
5. 保存时用新模板重新识别还没处理的待处理项：认得出的通知原来的待处理项关闭，按模板重新入账或换成新的待处理原因（例如还要选卡）；
   已经有流水入账的通知不动，避免重复记账。
6. 「我的 › 自动记账 › 识别模板」：点一个模板编辑（按原来的标识保存，`TemplateDAO.save`），往左滑删除（和首页的流水一样，点「删除」后从这一行弹出确认菜单）；编辑页里没有删除。
   模板里没有原文，编辑时用 `MessageTemplates.sample` 把写法还原成一条示例（金额 100.00、尾号 1234、对方「对方」、其他数字 0），圈好原来的位置；不改原文直接保存得到同样的写法。
7. **「不记」**：通知记上的、原文还在的流水，详情最下面有「不记」（确认菜单「以后这种通知都不记」，`LedgerBackend.skipRecord`）：
   删掉这笔，并把收到它的每条通知（短信、推送各一份）里这一笔所在的句子记成一条「不记」的写法——数字全换成任意数字，没有圈出金额（`MessageTemplate.isSkip`），文字太少时和做模板一样往前多取几句，仍然太少就只删除。
   识别时最先看「不记」的写法（`MessageTemplates.skips`），认得出就整条不记（`skipped`）。不加新的列：旧版本读到它也认不出任何通知。
   识别模板列表里写「不记」，不能编辑，往左滑删除。不在设置里单独放屏蔽列表。

8. **截图模板**（[ADR 0028](../../decisions/0028-ios-swift-screenshot-templates.md)）：截图上的字每次识别都不太一样，按原文对很难对上，所以截图另有一种模板：
   打开留着的截图（「待处理 › 没认出的截图」，或者「识别模板」右上角「导入」里从相册选截图），点框选金额、卡号、对方，选类型和记到哪个账户。
   模板存页面上固定的字和每样东西挨着哪段字，不存截图和数字。列表里在「截图」那一块，不能编辑，往左滑删除。
