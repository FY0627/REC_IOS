# 冻结、转账和余额

## 完成扣款和冻结

- 括号里的时间说明（「（交易预授权时间10月30日10:20）」）说的是之前那一步，不决定这笔的性质和状态，所以「完成扣款…（交易预授权时间…）」是 `posted`。
- 这个时间记在 `EventDraft.holdTime`。入账时，同一张卡上只有一笔冻结是这个时间（精确到分钟）时，这笔冻结改成 `holdReleased`，并关联到完成扣款（`IngestEngine.closeHold`），
  流水详情里能看到关联的交易。不比较金额：最终扣款可以和冻结金额不同，币种也常常不同。
- 找不到、或者有几笔冻结都是这个时间时不改，不猜；通知没写预授权时间时同样不改，冻结留在卡片详情里。
- **了结的冻结收进扣款里**（2026-11-11）：关联到一笔已入账扣款的 `holdReleased` 在流水列表里不单独显示（`RecordDAO.closedHoldHidden`），扣款的详情里有「预授权」一栏；冻结的详情里「完成扣款」下面可以「取消了结」，改回冻结。
  撤销预授权、解冻的通知（没有关联扣款）照常显示。
- **手动了结**：冻结的详情里「了结冻结」，打开和「合成一单」一样的面板（`HoldCloseView`）：上面是这笔冻结，下面从同一个账户冻结之后 45 天内已入账的流出里选一笔扣款，和冻结时写的实扣一样的排在前面、标「和实扣金额一样」（`LedgerBackend.holdCaptureCandidates`）；也可以选「没有扣款（已撤销）」，右上角确定。
  不按金额自动了结：金额一样也可能不是同一单。
- **招行 App 推送和 95555 短信是同一笔**（`IngestEngine.detailTwin`、`mergeDetail`）：推送只写「您绑定在Apple Pay上的账户…扣款人民币 126.84」，没有时间、商户和预授权时间；短信写全了。
  招行 App 的「动账提醒」推送写到了分钟（「11月2日19时30分支出人民币86.50元」），但没写商户、看不出是什么交易，和写全的短信（「在支付宝-鲜丰超市快捷支付」）也是同一笔：两边交易时间相差不到 2 分钟就算对得上（两边都写了商户的不算）。
  同账户、同金额币种方向和状态，系统时间 20 分钟内，一边没写交易时间（或者只写了金额）、另一边写全了，都是银行的通知，已有的那笔只有一条来源，而且只有这一笔对得上时，合成一笔：
  推送先到，短信补上交易时间、商户（推送认不出的交易性质也换成短信的），去重键换成按时间算的，再按短信里的预授权时间了结冻结；短信先到，推送只加一份来源。
  以前这种情况短信进待处理「可能与已有流水重复」，冻结一直挂着。已经合过一次的那笔不再合：同一张卡连着两笔一样的金额时，第二条推送照常交给用户判断。

## 内部转账、还款、退款

- 自己两张卡互转：两边流水都保留；金额相同、方向相反、30 分钟内且唯一匹配（或正文写明对方尾号是自己的卡）→ 同一转账组，不计入收支。
- 没配对到自己另一张卡的转账（转出 / 转入）：照常入账，先按转给别人统计（转出算支出、转入算收入），
  并放在「待处理 › 待分类」里：选「转给自己的账户」→ 算转帐，不计入收支，并记住这个对方；直接选分类 → 算转给别人。
  流水详情里可以随时改（`records.transfer_party`）。
- 只有一边有通知的转帐（微信提现到银行卡：银行卡记成收入，微信没有通知、手动记了支出）：流水详情 › 合并 › 转帐，
  选另一个账户方向相反的那一笔，合成一笔转帐，和配对的转帐一样不计入收支；两笔、来源和原文都留着，金额可以不同（差额是手续费）。
  详情里「拆开」回到原来的支出、收入和分类（[ADR 0014](../../decisions/0014-ios-swift-entry-types-and-categories.md) 修订 2026-11-05）。
- 信用卡还款：借记卡付出与信用卡收到都记为「还款」，不计入支出/收入；能配对时同组。信用卡上原有的消费才是支出。
- 退款 / 冲正：新记一笔流入，能唯一找到原交易时建立关联；原交易不覆盖、不删除。

## 余额

- **初始余额**：用户在添加卡或「卡片信息 › 编辑」里填写的「现在」的余额（可填欠款，即负数），每个币种一个。
- **推算余额**：从初始余额出发，加上之后到达的已入账流水；添加账户时没填余额的币种从 0 开始（2026-10-30 起）；更早添加、没填过的账户显示「未知」，不计入净资产，可在卡片信息里填校准余额。
  多币种账户每个币种分别推算，不做换算。流水用通知到达手机的时间和初始余额比较（通知内时间是银行所在地时间，和手机时区可能不同）。
- **卡里没有的币种的交易**（例如港币卡付人民币）：按主币种扣款，计入主币种余额。用户填了或通知写明了实际扣款就用它，否则按交易当天的汇率估算；
  还没有任何汇率时先不计入（[ADR 0013](../../decisions/0013-ios-swift-record-editing-and-foreign-charges.md)）。
- **多币种账户这个币种不够**（恒生：人民币不够就扣港币）：信用卡以外的多币种账户收到消费通知，这个币种（不是主币种）的余额已知，
  可用余额（推算余额减还没结清的冻结）不够这一笔时，整笔从主币种扣，按汇率估算；完成之前预授权的那笔不判断。入账时判断一次并存下来，
  记账结果通知写明「人民币余额不足，按港币扣约 HK$…」，错了在流水编辑里改扣款币种（[ADR 0018](../../decisions/0018-ios-swift-charge-currency-and-converted-cards.md)）。
- **冻结**不计入余额，另外合计，算可用余额用。
- **不使用银行通知里写的余额**（2026-10-26 起）：很多银行的通知不带余额，带的写法和含义也不统一（信用卡尤其如此）。
  解析器仍会认出余额字段并记在流水上（`balanceAfterMinor`），但不再保存余额快照，也不用它推算卡片余额。
  旧版本保存的余额快照（`balance_observations` 表）保留在数据库里，不再读取。
