# 0028 iOS Swift 版：认不出的截图先留着，在截图上点出金额做成模板

- 状态：已采纳（`ios-swift/`），修订 [ADR 0021](0021-ios-swift-payment-screenshots.md) 的「截图识别完就丢掉」
- 日期：2026-11-21

## 背景

截图记账靠 App 自带的读法（`ScreenshotParser`）认微信、支付宝的页面。用户实际用到的 App、银行、页面版式太多，一种一种去适配做不完，
开发者手上也没有那么多样本（例如余额宝「转入成功」页，2661821 才补上）。识别模板（[templates](../features/ios-swift-auto-bookkeeping/templates.md)）
只认通知的文字：截图上的字每次识别都不太一样（对勾认成「•」「♥」、换行变化、广告每天不同），按原文一字不差去对很难对上；
它也说不出「记到余额宝，截图上的卡是另一边」。

讨论过学 ReRime 的做法：定一种规则文件，让用户自己用 AI Skill 做规则再导入。没有选：要把银行短信、截图交给云端 AI，和本地优先不合；
会用 Claude Code 的记账用户很少。用户提出直接在 App 里打开截图、点出哪里是金额、哪里是账户。

## 决定

**截图先留着**（`Bookkeeping/App/ScreenshotInbox.swift`）：截图记账（快捷指令、从相册选）一笔也没认出（不是点过「不记」的），或者有进了待处理的，
截图原样存在 App 的数据目录里（不放进相册），另外存识别出的每段字和位置。

- 「待处理」里多一块「没认出的截图」：缩略图、为什么留着、时间，「做成识别模板」「删除」，右上角「全部删除」，删除只提示「删除后不能恢复」。首页「待处理」那一行也算上它的张数；
- 截图做成模板后删掉，用户也可以自己删；一直没人管的，和通知原文同一个保留期限（「我的 › 数据」里的天数）到期删掉；
- 只在这台手机上：不同步、不进导出和备份；文件保护等级 `completeUntilFirstUserAuthentication`（快捷指令锁屏时也会跑）；
- 进了待处理的截图，待处理那一条的「做成识别模板」也打开这张截图；
- 快捷指令动作的说明从「截图不保存」改成「认不出的截图先留在 App 里，做成识别模板或删除后清除」。

**截图模板**（`BKModel/ScreenTemplates.swift`、`BKBackend/Parsing/ScreenTemplates.swift`、`UI/Pending/ScreenTemplateEditorView.swift`）：

- 编辑页和通知模板一样像写邮件：名称、类型（一个菜单）、记到排在一张卡片上，下面是截图，识别出的每段字画成框；点框选「金额」（必选）、「卡号」「对方」，和记账一样选支出 / 收入 / 转帐，选「记到」：
  「自动」（点了卡号时是「按截图上的卡号」找卡）或者一个账户。选了账户时截图上的卡号是转帐的另一边：转帐先算这个账户的收入（支出），
  卡上那笔银行通知来了再合成转帐（`IngestEngine.pairWithCard`，和余额宝转入一样）；
- 保存前用这个模板读一遍这张截图（「试读」），读不出来不让保存；
- **模板里存什么**：没点到、不含数字的段是「页面上固定的字」（整理全角繁体、去掉两头的符号和空白、不分大小写）；
  点到的每样东西存「挨着哪段固定的字、在它哪边」：同一行左边（`right`，标签和值）、上面（`below`，下面第一个像金额 / 卡号 / 名字的）、下面（`above`）。
  找法要在这张截图上找回点到的那一段才算数，按同一行、上面最近、下面最近的顺序试。不存坐标（屏幕大小、广告长短不同），不存截图，不存截图上的数字；
- **认截图**：排好的行和段（`ScreenLayout.text`：一行里各段两个空格隔开，段里的空白缩成一个）上，固定的字至少 60% 在（挨着字段的那几段必须在），
  按找法读出金额（要有两位小数，后面跟着 % 的不算；整段只是一个带 ¥ 的金额、后面紧跟着多一位数字的，是旁边的「ⓘ」认成了数字，多的这一位不算）。
  识别截图时也先拆：一段开头、结尾隔开一点、明显小一号（不到 55% 高）的一两个字母或数字，按 Vision 每个字的框拆成单独一段（`ScreenLayout.splitIcons`，`ScreenshotReader`），图标就不粘在金额、标签上；Vision 只给整个词的框时拆不了，和以前一样、卡号（括号里、「尾号」后面、单独的 4 位数）、对方。标签和值认成一段的（「付款方式 招商银行储蓄卡(1234)」）也认；
- 入账时截图先看「不记」的写法，再看截图模板（新做的在前），再看通知模板，都没有才用自带的读法；
- 保存后用它重新识别待处理里的截图（`IngestEngine.reapply(_: ScreenTemplate)`），这张截图没进待处理的再按模板记一遍，然后删掉这张截图；
  从「识别模板」右上角「导入」里选的截图只做模板、不记账，编辑页关掉就删；
- 存在 `screen_templates` 表（迁移 14）：页面上的字和找法是一段 JSON，记到的账户单独一列，导入备份时和别的表一样换成这台手机上的账户；
- 「识别模板」右上角只有一个「导入」：同一个页面里一个像备忘录的输入框，直接粘贴或打通知文字，光标离开就认一遍；输入框右下角的圆按钮从相册选截图（选了就换成截图模板的编辑页）。列表里分「通知」「截图」两块，往左滑删除。

**版面骨架：不存截图也能改模板**（2026-11-22 补充）：用户做完模板不知道好不好用，填错了只能删了重做。
照通知模板的做法（模板不存原文，编辑时用 `MessageTemplates.sample` 还原成示例），截图模板另存一份版面骨架（`ScreenTemplateLayout`，`ScreenTemplates.skeleton`）：

- 存这张截图识别出的每段字和位置（归一化，留 4 位小数）和截图的宽高比，放在 `body_json` 里的 `layout`，不用改表；一个模板几 KB，原截图 1 MB 以上；
- 点到的金额换成 `100.00`、卡号换成 `1234`、对方换成「对方」，其他数字都换成 0。没有数字的字照原样：它们本来就是固定的字（`anchors`）；
  含数字的段里的字也照原样（「示例银行借记卡(0000)」），所以会多存银行名这类字。只在这台手机和它的备份里，和通知模板存的原文写法一样；
- 行、段和原来一样多，固定的字不变：用同样的找法在骨架上找回点到的几段（`ScreenTemplates.picks(for:in:)`），重新做出来的模板和原来一样，试读读出示例值；
- 编辑页照骨架画一张白底的页面，每段字写在原来的位置上，点框改选，类型、记到、名称照旧；按原来的标识保存（`LedgerStore.updateScreenTemplate`），待处理里的截图按它重新识别；
- 认截图不看骨架。这个字段加上之前做的模板没有骨架，不能编辑；
- 先放在「我的 › 开发与调试 › 编辑截图模板」开关后面：打开后列表里有骨架的截图模板点开编辑，关着时和以前一样只能左滑删除。新做的模板不管开关都存骨架。

## 限制

- 快捷指令「从图像中提取文本」交过来的文字没有截图，也没有段和段之间的空隙，不会留着；用它认时每行只算一段，标签和值在同一行的靠「认成一段」那条规则；
- 每种页面每个人要做一次；页面改版后模板认不出，截图又会留下来，再做一次；
- 固定的字太少（合起来不到 6 个字）的截图做不了模板，免得认错别的截图；
- 广告刚好插在固定的字和要找的东西中间、又长得像要找的东西时会读错；
- 换演示账本（ADR 0025）时留着的截图不跟着换。
