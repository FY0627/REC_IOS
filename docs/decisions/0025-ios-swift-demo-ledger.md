# 0025 iOS Swift 版：演示数据（单独的演示账本）

- 状态：已采纳（`ios-swift/`），第一版，等真机录屏验证
- 日期：2026-11-13

## 背景

官网（首页、隐私政策、技术支持；简体、繁體、English）每段功能都要在手机框里放一段录屏或截图：自动记账、截图记账、灵动岛选分类、卡包、多币种净资产、待处理，
另外首页、资产、统计、我的四张截图。以前的素材是真机用真实账本录的，录完要给卡号、收款方打码。App 没有演示数据。
仓库是公开的，演示数据里不能有真实的商户、卡号、人名。

## 决定

**一个开关，一份单独的账本。** 「我的 › 开发与调试」（连点 7 次版本号才出现）里加「演示数据」开关（`ProfileView`、`LedgerStore.setDemo`、`App/DemoMode.swift`）：

- 打开：账本换成 `Application Support/Demo/ledger.sqlite`，卡面图片、导入前的副本都跟着它放在 `Demo/` 下（`AppServices.databaseURL`）。
  真实账本 `Application Support/Ledger/` 演示期间不读、不写、不覆盖。
- `AppServices` 缓存的账本带着文件路径，路径一变（开关一换）下次取的时候就换成另一个；界面、App Intent、通知按钮、灵动岛用的都是它，所以自动记账、
  截图记账、灵动岛选分类在演示期间都记到演示账本里。
- 每次打开都**重新生成**（先删掉上次的 `Demo/`），流水按当天往前排，每段录屏都从一样干净的状态开始。关掉时删掉 `Demo/`。
- 换账本时结束灵动岛上的实时活动、清掉排着的（那一笔是另一个账本的）；整个界面按「账本代次」重建（`BookkeepingApp` 的 `.id`），
  停在卡片详情、编辑里的页面都关掉。

**设置整份存、整份换回。** 打开时把 App 自己的 UserDefaults（`persistentDomain`）存一份（`demo.savedSettings`，二进制 plist），
关掉时多出来的键删掉、变了的写回去，再让语言、图标、主题色、汇率马上生效。演示期间改的主要币种、主题色、记账结果、语言、统计范围、汇率缓存都恢复原样。
没有一项一项列：以后加的设置也自动在里面。系统框架写进同一个域的键也一起换回打开前的值，影响不到账本。
汇率缓存打开时换成演示账本里最近一天的汇率，净资产和换算合计才有数。

**按打开时的 App 语言生成**（问过用户）。商户、备注、人名、自己加的分类名有简体、繁體（台湾用语）、English 三套；
默认分类、银行、现金和钱包的名字账本里存的是简体，App 显示时本来就按语言换。录另一种语言：关掉 → 换语言 → 再打开。

**生成方式：走真实的入账流程**（`BKBackend/DemoLedger.swift`，`LedgerBackend.seedDemo`）。不直接往表里插：

- 用一个可以拨的时钟（`DemoClock`）开第二个 `LedgerBackend`，按时间顺序把编好的通知交给 `ingest`、截图文字交给 `ingestScreenshot`、
  手动记的交给 `addRecord`，入账后像用户一样 `setCategory`。解析、认账户、合并冻结、外币扣款、学分类都是真的，演示出来的样子就是用户会看到的样子；
  解析器以后改了，演示数据不对时测试会失败（`DemoLedgerTests`）。
- 通知照真实的写法编（只照格式，内容一律另编）：招行 App 动账提醒和快捷支付短信、招行 Apple Pay
  预授权冻结和完成扣款（日元）、中行「商户：」、恒生「無卡支付」（人民币、美元、港币），微信账单详情、转账、红包截图，支付宝账单详情截图。
- 固定种子的随机数，同一个「现在」生成的一样。生成完标记「学习已回放」「待处理已按现在的读法读过」，App 打开账本时不再做一遍。

**内容：一个用了三个月的人**（用户要求能展示分类推荐）。

| 部分 | 内容 |
|---|---|
| 账户 | 招商银行借记卡（工资卡）、恒生多币种卡（港币、人民币、美元）、中国银行信用卡、微信支付、支付宝、现金；尾号都是编的 |
| 流水 | 90 天约 360 笔：工作日早餐（现金）、地铁、咖啡、午饭（微信截图）、晚饭或买菜、便利店、网购；周末早午饭、逛街、电影、火锅（有时 AA，朋友转回来一半）、打车；每月房租、工资、话费、燃气、健身、订阅（美元）、还信用卡、给钱包充钱、取现、返现、利息 |
| 只有一次的 | 日元网店预授权、第二天按人民币完成扣款（冻结收进扣款）；同卡港币换美元；火车票；给妈妈的礼物；香港演出票（港币） |
| 待处理 | 没添加的浦发卡、微信付款成功页没写用什么付的、手动记过又来了银行通知（可能重复）；另有一笔转给朋友、还没确认对方的转账 |
| 汇率 | 每天一份（以美元为基准），有一点波动 |
| 分类 | 自己加的「饮食 · 买菜」「订阅」「返现」；常去的店连续选同一类，后来自动归类（约一半）；便利店轮着选饮料零食、日用品，超市偶尔记成日用品——只排在推荐前面 |

**模拟消费在演示账本里**（`Simulation`）：不建「模拟卡」，记到演示的中行信用卡上，用中行的写法；商户和演示数据里的店同名、按演示的语言、不带「模拟·」。
早餐、午餐、咖啡、打车是常去的店，模拟出来就自动归类；便利店两个分类都在推荐最前面；晚餐是没去过的店，按常用分类推荐。
一键清除只删模拟的那几笔，卡和学到的分类留着。

## 后果

- 打开要几秒（低端机上生成几百笔），开关旁边转圈，换好之前不能再点。
- 演示期间真实的银行通知记进演示账本，关掉后就没了；只在录屏时打开。
- 演示期间导出的是演示账本；导入只进演示账本，设置在关掉时换回去。
- App 在生成到一半被关掉：下次打开还是演示账本（不完整），关掉再打开就重新生成；演示账本的文件不在了就自动回到真实账本。
