# 0018 iOS Swift 版：多币种账户余额不够时整笔换主币种扣款，卡包里的余额换算成主要币种

- 状态：已采纳（`ios-swift/`）
- 日期：2026-11-03

## 背景

- 恒生多货币扣账卡：交易币种的户口结余足够就扣这个币种，不够时整笔换算成港元、从港元户口扣（恒生多货币扣账卡常见问题）。
  原来 App 只要账户有这个币种就记在这个币种，余额会扣成负数；只有账户没有这个币种时才按主币种扣（[ADR 0013](0013-ios-swift-record-editing-and-foreign-charges.md)），
  而且扣款币种只能是主币种，用户没法改。
- 众安的卡只能用港币付款，通知直接写港币金额（`消费 HKD 0.25`），现有逻辑已经对。
- 卡包里每张卡显示自己的币种，币种不同的卡放在一起没法比较；多币种的卡只显示主币种的余额，其他币种要进卡片信息看；
  详情里换了币种，卡面也还是主币种。

## 决定

**扣款币种**

- 每笔流水可以记下从账户的哪个币种扣款（入账）：`records.settlement_currency`，模型里是 `LedgerRecord.chargeCurrency`；
  实际金额仍在 `settlement_minor`（`settlementMinor`），没有时按汇率估算（`ChargeCalculator`）。
  表结构不变：原来这两列只存「账户没有这个币种时的实际扣款（主币种）」，旧数据的含义不变，不用迁移。
- 这笔从哪个币种扣（`LedgerRecord.chargedCurrency(in:)`，查询里是 `RecordDAO.chargedCurrency`）：
  记下的币种（账户还有它时）→ 这笔自己的币种（账户有时）→ 主币种。
- 和默认的一样、又没有实际金额时不记（`LedgerRecord.setCharge`）。所以账户以后加上这个币种，按汇率估算的那些流水就算在新币种里；
  填过实际金额的仍从原来的币种扣，因为那时银行扣的就是它。这一点改了 ADR 0013 的说法（原来填过实际金额的也会移过去）。
- 自动记账（`IngestEngine.commit`）：
  1. 账户没有这笔的币种，通知括号里写了扣的是账户哪个币种多少（「JPY1000.00（人民币48.00）」）：用它。原来只认主币种。
     账户有这个币种时，括号里的多半只是折合多少，不用。
  2. 多币种账户（信用卡除外）的消费，这个币种不是主币种、余额已知，可用余额（推算余额减还没结清的冻结）不够这一笔：
     整笔从主币种扣，按汇率估算；括号里写了主币种多少就用它（`IngestEngine.lacksBalance`）。
  3. 完成之前预授权的那笔（通知写了预授权时间）不判断：那笔冻结这时还没关掉，算进去会重复。
- 判断在入账时做一次，结果存下来，之后余额变了不重新判断。不进待处理：判断错了在流水编辑里改扣款币种和实际金额。
  记账结果通知写明，例如「尾号 0004 卡，消费，¥80.00，人民币余额不足，按港币扣约 HK$86.67，记账成功」。
- 手动记一笔、编辑流水：多币种的卡多一行「扣款币种」（收入是「入账币种」），默认和自动记账一样；
  扣的不是这笔的币种时可以填实际金额，空着提示按汇率大概多少。转帐不选（转出的账户没有这个币种时仍按主币种）。
- 余额（`LedgerBackend.balanceSummaries`）：每个币种加上从它扣款（入账）的流水，换算来的按实际金额或汇率估算；
  还在冻结中的流出另外合计（`AccountBalanceSummary.openHoldsMinor`），可用余额 = 推算余额 − 冻结。
  卡片详情按币种看流水也按扣款币种（`RecordFilter.currency`）。
- 只整笔换，不做一半人民币一半港币：恒生说的是把交易金额换算成港元扣。

已知限制：

- 余额是推算的：漏记了一笔人民币收入，会把够的误判成不够。
- 添加账户时没填余额的币种从 0 开始（2026-10-30 起），这个币种的每笔消费都会换成主币种扣。
- 没有完成通知的冻结（例如中行只发「已冻结」）一直算在冻结里，会让可用余额偏少。

**卡包里的余额**

- 卡包里每张卡只显示一个金额，都按最新汇率（和净资产用的同一份）换算成「我的」主要币种，换算过就写「≈」
  （`AccountBalances.stackText`）；多币种的卡是各币种换算后的合计。没有汇率、有余额的币种缺汇率时，显示账户主币种（原币种）的余额，
  不显示少算了一部分的合计；余额未知的币种不计入。本来就是主要币种的卡不写「≈」。
  （2026-11-03 第一版只换算多币种的卡，用户要求卡包里全部换算。）
- 打开详情：卡面显示账户自己的币种（多币种的卡是主币种）的余额；在「交易记录」旁换了币种，卡面换成那个币种的余额，
  右下角写这个币种，代替「HKD +2」。返回卡包时换回换算后的金额。卡面文字的更新和转场动画在同一次提交里（`WalletController.refreshCard`）。
- 不在卡面加第二行小字，详情里也不加一排各币种的余额：一次只显示一个金额。
- 这改了 [ADR 0011](0011-ios-swift-multi-currency-and-rates.md)「卡面始终显示原币种、不做换算」。

## 备选方案

| 方案 | 结论 |
|---|---|
| 余额不够时先按原币种入账，进待处理让用户确认扣款币种 | 不采纳：恒生的规则是确定的，每笔都确认是多余的操作；余额变负也比悄悄换币种显眼，但通知里已经写明 |
| 每个账户设置「余额不够时扣哪个币种」 | 不采纳：用户只有一张多币种卡，规则就是主币种；众安的通知直接写港币 |
| 扣款币种另加一列 | 不采纳：`settlement_currency` 正好是这个意思，旧数据不用迁移 |
| 卡包里多币种卡加一行其他币种的余额，或者详情里加一排余额 | 不采纳：用户要一次只显示一个金额 |
| 卡包里单币种的卡仍显示原币种 | 第一版这样做，后来不采纳：用户要卡包里的钱都按主要币种看，原币种在详情里看 |

## 影响

- 表结构不变。`LedgerRecord.settlement` 换成 `chargeCurrency` 和 `settlementMinor`，`RecordRow.isForeignCurrency` 换成 `isConverted`；
  `ManualEntry`、`RecordEdit` 加 `chargeCurrency`；`IngestItem` 加 `charge`、`insufficientBalance`（记账结果通知用）。
- `RecordDAO.postedAfter`、`postedForeign` 合成 `forBalance`：每个账户读一次已入账流水和冻结。
- 卡面在打开和返回详情时各多一次更新（只有那一张卡），要在真机上确认转场（[ADR 0012](0012-ios-swift-wallet-core-animation.md)、b73）没有变差。
- 不引入第三方依赖，App 仍然不联网。
