# 0017 iOS Swift 版：在本机学习分类，记账结果通知上选分类

- 状态：已采纳（`ios-swift/`）；取代 [ADR 0014](0014-ios-swift-entry-types-and-categories.md) 修订里的「不猜分类」。
  记账结果通知上的按钮和「通知类别在发通知前注册」已被 [ADR 0020](0020-ios-swift-notification-category-picker.md) 取代（通知扩展，大类、小类在一处选完）
- 日期：2026-11-02

## 背景

识别和入账可靠之后，每笔自动记账的消费都进「待分类」，都要手动选，不够自动。目标是少点几下：常用分类排在前面，把握很大时才自动归类，记账结果通知上就能选分类。

不用苹果智能：真机试过，34 条里有 8 条会记错（已去掉）。不联网。像输入法一样，只按用户自己以前的选择学习。

只靠商户名不够：中行的通知没有商户；众安只写 `ALP*QRCode0055`，恒生的微信支付有时只写 `Scan QR code`，这些不是真商户；「财付通-美团」要分出渠道和商户；招行的商户带地址、城市和邮编，冻结和完成扣款还写得不一样。

## 决定

**认商户**（`BKBackend/MerchantName.swift`）：去掉支付渠道前缀（「财付通-」「支付宝-」「WEIXIN*」「PAYPAL *」）、反斜杠后面的地址、末尾的邮编、国家和城市、括号里的分店，不分大小写、全半角和繁简。

只有渠道、收款码、打码的账号、纯数字，和 `某某*一串码` 这种收款通道（下面可能是很多家店），都不算商户。认不准时宁可学不到一起，也不把两家店当成一家。

**学习**（`BKBackend/CategoryLearner.swift`，迁移 11 的 `merchant_categories`，键是「类型|商户」）

| 情况 | 处理 |
|---|---|
| 用户选了分类（待分类、编辑流水、通知按钮、手动记一笔写了商户） | 这个分类选过的次数和连续次数 +1，这个商户别的分类连续次数清零 |
| 分类没变（同一笔反复保存） | 不算 |
| 同一个商户**连续 3 次**选同一个分类 | 下一笔自动归类，流水标 `records.category_auto` |
| 用户改掉一笔的分类 | 新分类从 1 开始数，要再连续够 3 次 |
| 看不出商户 | 不学习，绝不自动归类，只按常用分类排序 |

用「连续 3 次」，不用「最近至少 3 次并且最近一次也是它」：A、A、B、A 这样来回换的商户不该自动归类，而且改掉后不需要另外的重置逻辑。

**候选**（`CategorySuggestions`，最多 4 个）：这个商户选过的分类（最近选的在前），不够用最近 200 笔里用得最多的分类补齐，再不够按分类的顺序。隐藏的分类（包括隐藏大类下面的小类）、手续费、扣息不当候选。按时段分开学、三餐跟着时间、没学过的商户用小词库排第一，见 [ADR 0026](0026-ios-swift-meal-time-learning-and-lexicon.md)。

**现有规则在前面，不变**：转帐不用分类；手续费、扣息、工资、利息直接归类；退款跟着原交易。没确认对方的转账只排序，不自动归类，也不预先选分类（否则点「确定」就成了转给别人）。

**分类变动**

- 合并：学到的并到目标分类，次数相加，连续次数取大的（只有最近选的那个不是 0）。合并是说这两个分类一样，所以继续自动归类。
- 删除并改记到别的分类：学到的跟着流水走，但连续次数清零，要重新学。
- 删除、流水回到待分类：清掉，流水不再算自动归类。
- 隐藏：学到的留着，但不当候选、不自动归类。

**升级时回放**（`seedCategoryLearning`）：第一次打开新版本时把已有的手选记录按时间回放一遍，只做一次。通知写明的和退款不算。已经连续选够 3 次的商户，升级后下一笔就会自动归类。

**界面**

- 待分类面板：完整格子上面加一行「建议」。这个商户选过的分类预先选好，点一笔再点「确定」就够了。仍然要点「确定」才保存，可以先换（ADR 0014 修订里真机试用后定的）。
- 自动归类的流水：标题旁写「自动」（和「退款」一样的小标记），详情的分类后面写「自动归类」。
- 记账结果通知：只有选「全部」、这笔入账成功、还没分类或者是自动归类时才带按钮（`IngestNotifier`）。按钮是 3 个大类候选和「更多分类」：只看小类的名字（「考试」「买菜」）认不出是哪一类。
  没分类的通知末尾写「长按选分类」；自动归类的写「已归到「午餐」，长按可改」，候选去掉它所在的大类，点了算改掉。系统不让按钮露在收起的通知上，只能用文字提示。
  候选按钮直接保存，不打开 App、不用解锁、没有「确定」。选了有小类的大类时这笔先记在大类上，再发一条「已归到「饮食」，长按选小类」的通知，带 3 个小类候选和「更多分类」，不选就留在大类上：按钮点完不能在原来的通知上换一组。
  想要的分类不在候选里时，点「更多分类」或点通知本身，打开 App 并直接打开这一笔的选分类面板（和待分类同一个），里面有全部大类和小类，「转给自己」也在这里。没确认对方的转账点了候选就是转给别人。
- 大类、小类分两步选时算一次选择：这一笔刚选了大类、接着选它下面的小类，退掉大类那一次，记到小类上；选了大类而最近选的是它下面的小类时不算改主意，连续次数不断。一直只选到大类的，连续 3 次后自动归到大类。

**通知类别在发通知前注册，不在启动时注册**

按钮的文字写在通知类别上，启动时注册的类别做不到每个商户不同的候选。内容扩展能动态改按钮，但要多一个 target 和 App Group，免费签名和数据库都要改。

所以启动时只设代理（苹果要求在启动完成之前，`AppDelegate`），发通知前按这组候选注册一个类别：

- 同一组候选共用一个类别，标识里有分类的名称和图标，改了名称就是另一个类别。
- 注册是替换全部，所以留下还在通知中心的通知用到的类别，其余的清掉，类别不会越积越多。
- 注册没有完成回调：读回来看到了才发，等不到也照发。

苹果文档写的是通常启动时注册一次，没有提到动态注册；OneSignal 用过类似做法（每组按钮一个类别，定期清理）。最坏的情况是这条通知没有按钮，这笔照常留在待分类，不影响记账。

**点按钮不打开 App 也能写入**：动作不设 `.foreground`，系统在后台拉起 App 并通知代理。写入走现有的 `LedgerBackend`，账本的保护等级是 `completeUntilFirstUserAuthentication`，开机解锁过一次后锁屏也能写，和自动化入账一样。开机后还没解锁时写不了，这笔留在待分类。代理等写完才返回。

## 不做

- 按金额猜分类、用苹果智能、联网查商户（按时段推测三餐改由 ADR 0026 做了）。
- 同一个商户还没分类的流水一起归类：只有之后到达的才自动归类。
- 内置商户表（「星巴克」就是饮料）当成自动归类：每个人的分类不一样，学用户自己的（ADR 0026 的小词库只排推荐）。

## 已知限制

- 商户描述没写城市时（`SHOP NAME CN`），最后一个词会被当成城市去掉，两家店可能学到一起。卡组织的描述几乎都带城市，用户改掉一次就会停止自动归类。
- 平台型商户（美团既有外卖也有打车）：连续选同一个分类就会自动归类，下一笔不是这一类时要改掉一次。
- 没有写入 `records` 的商户键：改了流水的交易对方，已经学到的不跟着改。

## 影响

- 迁移 11：`records.category_auto`、`merchant_categories`，删除 `counterparty_rules`（一个键只能存一个分类，也早就不读写了）。
- 记账结果通知需要 App 启动时设好通知代理（`AppDelegate`），不再在发通知时才设。
- 单元测试和 CI 覆盖不到通知按钮和界面，要真机验证，见 [真机验收清单](../guides/ios-swift-device-checklist.md)。
