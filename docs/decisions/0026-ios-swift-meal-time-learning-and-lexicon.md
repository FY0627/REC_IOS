# 0026 iOS Swift 版：学分类按时段、三餐跟着时间、刚开始用的小词库

- 状态：已采纳（`ios-swift/`），修订 [ADR 0017](0017-ios-swift-learned-categories.md) 的「不按时间猜三餐」「不做内置商户表」
- 日期：2026-11-14

## 背景

ADR 0017 只按商户学：每个商户记选过哪些分类、最近连续选了几次，连续 3 次同一个分类下一笔就自动归类。用演示剧本走两周日常时用户发现：

- 美团中午点外卖连着选了午餐，下午 3 点在美团买了点东西选了「日用品」，连续次数就断了，第二天中午又要从头选三次；
- 美团晚上也点，学到的「午餐」到晚上就不对了；
- 刚开始用时什么都没学过，每一笔都从分类页的顺序开始找。

用户要的：吃饭时间一般是平时那一餐的时间前后一两个小时；先按 10 点前早餐、10–14 点午餐、16 点以后晚餐粗分，用户自己的数据多了就按自己的；
做一个小词库，付款信息里有某个词就大概对应某个分类，刚开始记账时体验好一点，用户自己的数据多起来就按用户的。

## 决定

**时段**（`BKBackend/MealTime.swift`）：早餐、午餐、晚餐的饭点，其余不是饭点。默认 5–10 点早餐、10–14 点午餐、16–24 点晚餐；14–16 点和 0–5 点不是饭点（用户选的）。
某一餐用户自己记成这一餐（默认分类里 `food.breakfast` / `lunch` / `dinner` 那三个）的流水最近 60 笔里够 5 笔，这一餐就换成它们时间的中位数前后 90 分钟。
两餐的范围重叠时算离中间近的那一餐。交易的时间按通知写的时分，没写到时分按收到的时间。

**按时段分开记**（`BKBackend/CategoryLearner.swift`）：每次选分类，同时记在「这个商户」和「这个商户在这个时段」下面（同一张表 `merchant_categories`，
时段接在商户后面，中间一个 `\u{1F}`；导出的「学到的分类」只列不分时段的）。

- **自动归类**：先看这个时段连续选够 3 次的；再看不分时段连续选够 3 次的。后者学到的是三餐之一时，换成这个时段的那一餐，不是饭点就不自动归。
  所以下午在美团选了一次「日用品」，中午那一档的连续次数不受影响；中午学会「午餐」的美团，晚上来一单就是「晚餐」。
- **推荐顺序**：这个商户这个时段选过的 → 不分时段选过的（三餐换成这个时段的那一餐）→ 这个商户什么都没选过时小词库猜的 → 最近 200 笔里常用的
  （这个时段用得多的在前）→ 分类页的顺序。
- 以前学过的账本没有时段：打开 App 时按已经选好分类的流水补一遍时段（`LedgerBackend.seedCategoryLearning`，只做一次），不分时段的不重复算。

**小词库**（`BKBackend/CategoryLexicon.swift`）：二十来组词，交易对方里有「地铁」「滴滴」「携程」「咖啡」「超市」「淘宝」「话费」「燃气」「影城」「药房」这类词，
对应默认分类里的一个；「外卖」「美团」「饿了么」「面馆」「火锅」这类吃饭的，按时段是早餐、午餐还是晚餐，不是饭点时是「饮食」大类。

- 只排在推荐的第一个，不自动归类（用户选的）；这个商户用户选过一次以后就按用户选的，词库不再出现。
- 只猜支出；只用默认分类的标识，用户删掉的分类不猜；猜的不当成「选过的」（待分类面板不预先选上）。

## 后果

- 同一个商户在不同时段用来做不同的事（早上地铁通勤、晚上加班打车）各学各的，也会按不分时段的连续次数自动归，学得不比以前慢。
- 三餐是按时间推测的：用户的饭点和默认差得多时，前几天会推测错，记够 5 笔以后按用户自己的。
- 「分类建议体检」按同样的规则重放，第一次去的店有了词库，第一个就猜对的会多一些。
- 推荐每次多读最近 200 笔的时间和三餐各 60 笔，都在数据库队列上，量很小。
